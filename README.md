# 周末去哪儿 · 上海

给大学生的周末探索决策工具 —— 可交互高保真原型。

**在线访问：** https://irischen-code.github.io/weekend-shanghai/

## 这是什么

大学生周末的真实困境不是"没有活动信息"，而是**信息过载后无法收敛决策**：活动散落在小红书、公众号、豆瓣同城、票务 App，每个平台都只回答"有什么"，没有一个回答"今天、这个天气、这点预算、我们仨，到底去哪"。

这个原型用三个输入（天气 × 预算 × 同行人数）把选择收敛成几个能立刻出发的选项，再用组队、打卡、攻略把一次出门变成可复用的内容。

## 功能结构

| 模块 | 解决的问题 |
| --- | --- |
| **推荐** | 加权匹配度排序，天气为硬约束，因子拆解可展开验证 |
| **组队** | 凑不齐人是决策后最大流失点，AA 拆分内置在队伍卡片 |
| **打卡** | 徽章驱动回访，同时为推荐算法沉淀真实偏好 |
| **攻略** | 路线/花费/耗时从打卡自动带出，发布成本降到"一句话" |

四个模块构成闭环：推荐 → 组队 → 打卡 → 攻略 → 回流为推荐供给。

## 推荐算法

匹配度 = Σ(因子得分 × 权重)

| 因子 | 权重 |
| --- | --- |
| 偏好 | 32% |
| 预算 | 26% |
| 人数 | 18% |
| 天气 | 14% |
| 新鲜度 | 10% |

天气额外作为**硬约束**：雨天对露天项目施加 −45 分封顶惩罚并在卡片标注原因。原因是低权重降权仍可能让户外项排进前三，而"下雨天推露天市集"会直接摧毁用户信任 —— 宁可少推，不可推错。

页面上切换晴/雨、拖动预算、改变人数，分数与排序均实时重算。

## 关键指标

北极星指标：**周活跃用户的周末成行率**（打开且当周产生一次打卡的用户占比）。

选它是因为它同时约束推荐质量与转化链路 —— 只优化点击会推出标题党，只优化打卡会忽略推荐准度。

## 技术说明

单文件静态页面，无构建步骤、无运行时依赖。字体来自 Google Fonts，其余全部内联。

## 数据说明

原型中的活动、价格、路线为**演示用样本数据**，非真实商户信息。地点与地铁线路参考上海真实地理信息。交互与推荐逻辑为真实可运行的前端实现。
